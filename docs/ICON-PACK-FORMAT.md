# Fenestra icon pack format (v1)

A Fenestra icon pack is a `.zip` file. Fenestra never ships or downloads Microsoft
assets itself: packs are produced by the user from their own Windows installation
(with *Fenestra Icon Extractor* for Windows) or by third parties under their own
licences, and imported by the user.

```
pack.zip
├── fenestra-pack.json          (required)
├── fonts/                      *.ttf / *.otf          -> ~/.local/share/fonts/fenestra-pack/<id>/
├── cursors/                    *.cur / *.ani (raw)    -> converted to Xcursor on import
├── assets/                     same layout as /usr/share/fenestra/assets
│   ├── battery/  status/  power/  consent/  search/  folders/  branding/  menu-icons/  hello/
├── icons/                      freedesktop icon theme (index.theme + dirs) -> ~/.local/share/icons/<theme>/
└── raw/                        optional untouched source files (e.g. Sysbatt.ttf, imageres groups)
```

`fenestra-pack.json`:
```json
{
  "format": "fenestra-icon-pack",
  "version": 1,
  "id": "windows-11-user-export",
  "name": "Windows 11 (exported from my PC)",
  "generator": "Fenestra Icon Extractor 1.0",
  "source": {"os": "Windows 11", "build": "26200.6584", "locale": "es-ES"},
  "created": "2026-11-05T20:00:00Z",
  "contents": ["fonts", "cursors", "assets", "icons", "raw"],
  "icon_theme": "Fenestra-Windows",
  "cursor_theme": "Fenestra-Windows-Cursors",
  "accent": "#0078D4",
  "licence_note": "Personal export of files from the user's own Windows licence. Do not redistribute."
}
```

Optional fields and files (importers ignore anything they don't know):

| Field / file | Meaning |
|---|---|
| `accent` | `"#RRGGBB"`, the user's Windows accent colour (`HKCU\Software\Microsoft\Windows\DWM\AccentColor`) |
| `source.version`, `source.edition` | Windows display version (e.g. `25H2`) and edition ID |
| `cursor_scheme` | `{"name": "...", "roles": {"Arrow": "aero_arrow.cur", ...}}`: the user's pointer scheme (`HKCU\Control Panel\Cursors` role -> file in `cursors/`) |
| `assets/branding/settings.png` | Settings app icon (256 px), in addition to `icons/<theme>/256x256/apps/fenestra-settings.png` |
| `assets/wallpapers/windows-desktop.*`, `windows-lockscreen.*` | current wallpaper / lock screen picture (only when the user opts in) |
Importers must validate `format`/`version`, refuse paths with `..` or absolute paths,
cap total size (1 GB), and install everything per-user (never system-wide).

## Proposal: glyphs and package logos (not implemented yet)

Status: proposal. Nothing in `apps/fenestra-icon-extractor` does this today. What the extractor
(v1.1.0, `src/Exporter.cs`) exports now: the font files themselves (`fonts/SegoeIcons.ttf` among
them), cursors, a freedesktop theme rendered from imageres/shell32/Edge icon groups
(`ThemeIcons`, 256/48/32/16 px), per-type file icons, the two folder arts, the Start logo SVG, the
search PNG, `Sysbatt.ttf`, and three app icons (Settings logo, `explorer.exe`, `Taskmgr.exe`).
It exports no individual glyphs and no Store/system package logos.

The list of what to export comes from `design/reference/icons.json`, which holds only names,
module ids, code points and where each icon appears in the reference screenshots; no artwork.

### Where the files come from (and why they are never in this repository)

The icon pack is generated by the user, on their own Windows PC, from their own licensed copy of
Windows: `C:\Windows\Fonts\SegoeIcons.ttf`, the `.mun`/`.dll` modules and the installed app
packages. It is never distributed by Fenestra: not committed to this repository, not attached to
releases, not produced in CI (the `icon-extractor` workflow only builds the program; it must never
run `--export` and upload the result), not downloaded by Fenestra OS. Microsoft's own page about
the font says it ships with Windows 11 and that it may be used for design and development "but you
may not ship it to another platform"
([Segoe Fluent Icons font, Microsoft Learn](https://learn.microsoft.com/en-us/windows/apps/design/iconography/segoe-fluent-icons-font)).
So the pack stays a personal export (`licence_note` as today), and Fenestra OS must look right
without it: every glyph and logo below has a Fenestra-original fallback in the shell's own assets.

### New pack contents

```
pack.zip
├── glyphs/
│   ├── glyphs.json                 index (required when glyphs/ exists)
│   ├── go-previous.svg             one SVG per named glyph of icons.json → glyphs[]
│   ├── …
│   └── u/E72B.svg                  optional: every glyph of the font by code point (--all-glyphs)
└── icons/Fenestra-Windows/<size>x<size>/apps/<name>.png   package logos (same theme as today)
    raw/appx/<PackageFamilyName>/<file>.png                   untouched logo files that were used
```

`"glyphs"` is added to `contents` in `fenestra-pack.json` when present. Importers that do not know
it ignore it (as with any unknown field); the format `version` stays 1.

### `glyphs/<name>.svg`

One file per entry of `glyphs[]` in `icons.json` that has a `codepoint` (entries whose code point
is `null`, i.e. glyphs not in Microsoft's public table, are skipped and listed as missing).

How the extractor would make them, all in memory, from `SegoeIcons.ttf` on the user's PC:

1. Open `%WINDIR%\Fonts\SegoeIcons.ttf` read-only (the file `ExportFonts` already reads).
2. Read the TrueType tables directly (a small reader in `src/`, no new dependency, so it keeps
   building on Linux with `EnableWindowsTargeting` and running under Wine): `head` (unitsPerEm,
   `indexToLocFormat`, font revision), `hhea`/`OS/2` (ascender), `cmap` (format 4 and 12 subtables,
   platform 3) to map the code point to a glyph id, `loca` + `glyf` for the outline. Composite glyphs
   are resolved by applying each component's offset/scale.
3. Convert the quadratic contours to an SVG path: on-curve points → `M`/`L`, off-curve → `Q`, the
   implied on-curve midpoint between two off-curve points inserted as TrueType defines it. Flip
   y (font units grow upwards): `y' = ascender - y`. Keep integer font units; no hinting, no
   rasterising, so the output is identical on every machine with the same font revision.
4. Write:

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 2048 2048" width="16" height="16">
  <path fill="currentColor" fill-rule="nonzero" d="M…Z"/>
</svg>
```

   `viewBox` = the em square in font units (use the real `unitsPerEm` and advance width read from
   the font; 2048 above is only an example). All Segoe Fluent glyphs share one advance width and
   origin, so glyphs line up when drawn on top of each other (the Learn page's "Layering and
   mirroring" section): the shell can layer, for example, a filled and an outline glyph. `fill=
   "currentColor"` lets the shell recolour it (text colour, accent, disabled). `width`/`height` are a
   hint only; the Learn page recommends 16, 20, 24, 32, 40, 48 and 64 px.
5. Mirrored forms (`…Mirrored` glyphs, for right-to-left locales) are separate code points; export
   them only when `icons.json` names them.

`glyphs/glyphs.json`:

```json
{
  "font": "SegoeIcons.ttf",
  "font_revision": "1.37",
  "units_per_em": 2048,
  "glyphs": {
    "go-previous": {"codepoint": "U+E72B", "glyph": "Back", "file": "go-previous.svg"},
    "notifications-disabled": {"codepoint": "U+F4BD", "glyph": "Snooze", "file": "notifications-disabled.svg"}
  },
  "missing": ["draw-freehand", "edit-select-text", "document-edit"]
}
```

(the revision and em size above are illustrative; the extractor writes what the user's font says.)

The names are the `glyphs[].name` of `icons.json` (freedesktop-style where one exists). They are a
separate namespace from `icons/`: `glyphs/folder-open.svg` (the FolderOpen glyph) and
`icons/Fenestra-Windows/*/places/folder-open.png` (imageres group 4) can both exist. The
extractor would carry the name → code point table compiled in (generated from `icons.json` at build
time, like `ThemeIcons`), never read `icons.json` at run time, and never embed outlines.

`--all-glyphs` (off by default) additionally writes `glyphs/u/<HEX>.svg` for every code point in the
font's `cmap` (more than the ~1,570 listed in Microsoft's public table), for people who want to pick
substitutes themselves.

Why SVG and not just the TTF: the TTF is already in the pack (`fonts/`) and the shell can keep
drawing text glyphs with it; the SVGs are for places that take icon files (icon themes, QML `Image`,
Plasma `Kirigami.Icon` sources), they need no font loading, and the importer can check them.

Importer: install to `~/.local/share/fenestra/packs/<id>/glyphs/` (per user, like everything else),
reject files that are not well-formed SVG with a single `<svg>` root, contain `<script>`,
`<foreignObject>`, event attributes or external references (`href` to anything but `#…`), and cap each
file (64 KB) and the folder (16 MB).

### Package logos (Store and system apps)

For `apps[]` entries with `module` `Appx` or `SystemApps` (Outlook, Microsoft 365 Copilot, Store,
Photos, Calculator, Clock, Snipping Tool, Media Player, Terminal, Camera, Feedback Hub, Weather,
Get Started, Windows Security, Notepad/Paint for `org.fenestra.Notepad`/`org.fenestra.Paint`, …):

1. Find the installed package for the current user by package family name (e.g.
   `Microsoft.WindowsCalculator_8wekyb3d8bbwe`) with `Windows.Management.Deployment.PackageManager
   .FindPackagesForUser("", familyName)`; take `Package.InstalledLocation`. This needs no admin
   rights and avoids listing `C:\Program Files\WindowsApps`, which normal users cannot enumerate.
   System apps without a Store family (`SystemApps\…`, `ImmersiveControlPanel`) use the known folder,
   as `ExportSettingsIcon` already does. The family names in `icons.json` are unverified
   (`verificado: false`, there is no Microsoft page listing them); a family that is not installed is
   reported as missing, never guessed.
2. Read `AppxManifest.xml` in that folder → `Applications/Application/uap:VisualElements/@Square44x44Logo`
   (e.g. `Assets\AppList.png`). That name is a resource base name; the files on disk are qualified
   variants: `AppList.targetsize-48_altform-unplated.png`, `AppList.targetsize-48_altform-lightunplated.png`,
   `AppList.scale-200.png`, `…contrast-black…`.
3. For each theme size (256, 48, 32, 16) pick: `targetsize-N_altform-unplated` with the smallest
   N ≥ size; else the largest `targetsize-*_altform-unplated`; else the largest `scale-*` (that one
   is plated: it carries the tile background). Never `contrast-*`. `altform-lightunplated` variants
   go to a second theme folder for the light theme (`icons/Fenestra-Windows-Light/`), only when
   they exist. Downscale with the same `IconCodec.Scale` used for the Settings logo.
4. Alternatively (simpler, same choice as the Start menu): `Package.GetAppListEntries()` (or
   `GetAppListEntriesAsync()`) → `AppListEntry.DisplayInfo.GetLogo(new Size(n, n))` returns the logo
   Windows itself picks for size `n`. The manifest path above is the fallback when the WinRT call is
   unavailable (for example under Wine).
5. Write `icons/Fenestra-Windows/<n>x<n>/apps/<name>.png` (adding `apps` to `index.theme` as
   today) and copy the files used to `raw/appx/<PackageFamilyName>/`.

`Exe` entries (Edge, PowerShell, `cmd.exe`, OneDrive) use the existing `AppIcon(...)` path (first
icon group of the executable or its `.mun`).

`bitmaps[]` of `icons.json` (classic file dialog toolbar, the Organize and View menus, the
task view button, the OneDrive tray icon) have no known module id yet. They are not exported. A
developer can identify them on their own Windows install with the existing `raw/icons/<module>/<id>.ico`
mechanism and record the id in `icons.json`; the artwork itself still never enters the repository.

### Checks (`tools/validate-pack.py`, to be extended)

- `glyphs/glyphs.json` exists when `contents` has `glyphs`; every `file` exists and every SVG file is
  listed; names match `^[a-z0-9][a-z0-9.+-]*$`.
- Each SVG passes the importer rules above.
- Logos: every `apps/` PNG is square and its size matches its folder.
